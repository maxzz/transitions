The current splitter is wrong on this repo: pnpm paths make almost everything land in a `.pnpm` chunk, scoped packages get truncated, and `react`/`react-dom` get torn apart. I'll replace it with a package-name extractor that handles those cases, using Vite 8's `codeSplitting` API.

The old splitter was not reading real package names. On this pnpm repo it almost always returned `.pnpm`, so vendor code did not split the way it looked like it would.

**What was wrong**

1. **pnpm paths.** A typical id is `node_modules/.pnpm/react@19.2.8/node_modules/react/...`. Taking the first segment after `node_modules/` yields `.pnpm`, not `react`.
2. **Scoped packages.** `@react-spring/web` was truncated to `@react-spring`.
3. **Windows slashes.** The split only looked for `node_modules/`.
4. **`react` / `react-dom`.** Those two must stay in one chunk; splitting them can break initialization.

**What “correct” looks like**

Use the **last** `node_modules/<pkg>` segment, keep `@scope/name` intact, and keep the React family together:
