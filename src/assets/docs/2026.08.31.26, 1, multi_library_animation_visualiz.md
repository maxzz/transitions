## Type / interface boundaries

### 1. Canonical model (library-agnostic)

```ts
type EngineId = 'spring' | 'motion' | 'gsap';

interface CanonicalTransition {
 from: AnimProps; // { x, y, scale, opacity, rotate }
 to: AnimProps;
 delay?: number;
 duration?: number; // optional — meaningless for physics springs
 ease?: EasingSpec; // tagged union, mapped per engine
}

type EasingSpec =
 | { kind: 'linear' }
 | { kind: 'cubicBezier'; values: [number, number, number, number] }
 | { kind: 'named'; name: string } // engine-specific subset
 | { kind: 'spring'; stiffness: number; damping: number };
```

Keep the canonical layer **small**. Advanced features (yoyo, stagger, timelines) stay in engine-specific params.

### 2. Schema (drives reusable controls)

```ts
interface ParamSchema {
 key: string;
 label: string;
 type: 'number' | 'range' | 'select' | 'boolean' | 'easing' | 'color';
 min?: number; max?: number; step?: number;
 default: unknown;
 group?: 'timing' | 'physics' | 'easing' | 'advanced';
 engines?: EngineId[]; // omit = all engines
 when?: (params: Record<string, unknown>) => boolean;
}
```

`ControlPanel` renders purely from `engine.schema + paramAtoms`.

### 3. Engine plugin contract

```ts
interface TransitionEngine<TParams extends Record<string, unknown>> {
 id: EngineId;
 label: string;
 schema: ParamSchema[];
 defaultParams: TParams;

 /** Best-effort map when switching engines */
 migrateParams(from: EngineId, params: unknown): TParams;

 /** Convert canonical + engine params → library config */
 toConfig(canonical: CanonicalTransition, params: TParams): unknown;

 /** React preview — each engine owns its integration style */
 Preview: React.FC<EnginePreviewProps<TParams>>;

 /** Optional: sample normalized progress 0→1 for easing graph */
 sampleProgress?(params: TParams, t: number): number;
}
```

### 4. Registry (lazy loading)

```ts
const engineRegistry: Record<EngineId, () => Promise<TransitionEngine<unknown>>> = {
 spring: () => import('./spring').then(m => m.springEngine),
 motion: () => import('./motion').then(m => m.motionEngine),
 gsap: () => import('./gsap').then(m => m.gsapEngine), // adds ~50kb+, load on demand
};
```

### 5. Jotai store shape

```ts
// src/store/3-visualizer.ts
activeEngineAtom: PrimitiveAtom<EngineId>
canonicalAtom: PrimitiveAtom<CanonicalTransition>
engineParamsAtom: Atom<EngineParams> // discriminated union
playingAtom, scrubTimeAtom
activeSampleIdAtom, activePresetIdAtom

// src/store/4-param-atoms.ts
paramAtoms(key) → atomsFamily keyed by `${engineId}:${paramKey}`
```

On engine switch: load new schema → `migrateParams` → reset `paramAtoms` family keys.

## API compatibility risks (flag early)

| Risk | Spring | Motion | GSAP | Mitigation |
|------|--------|--------|------|------------|
| **Duration vs physics** | Physics springs have no fixed duration | `type: 'spring'` approximates duration | Always duration-based | Hide or relabel duration for physics mode; show "approx length" read-only |
| **Easing representation** | Functions, config easing | Bezier arrays, named eases, spring | String eases (`power2.out`), CustomEase SVG | `EasingSpec` tagged union + per-engine mappers; graph only supports bezier/named subset |
| **Property model** | `animated` components | `motion` components | Ref targets, timelines | Canonical props: `x, y, scale, opacity, rotate` only in v1 |
| **Keyframes / sequences** | Limited | Native `keyframes` | Timelines, stagger | Engine-specific "advanced" schema group; not in canonical model |
| **React integration** | Declarative hooks | Declarative | Imperative (`useGSAP`) | Engine owns `Preview`; shared shell only passes `params` + `canonical` |
| **Repeat / yoyo / reverse** | `loop` config | `repeat`, `repeatType` | `repeat`, `yoyo` | Add only when engine is active; don't unify in canonical |
| **StrictMode double-mount** | Generally safe | Generally safe | Timelines leak without cleanup | `useGSAP` + `atomWithListeners` cleanup; follow existing `atomLoader` StrictMode guard |
| **Bundle size** | Already installed | Already installed | Not installed | `import()` on engine select; never static-import all three in `main.tsx` |
| **Param migration on switch** | tension/friction ↔ stiffness/damping | Approximate, not 1:1 | Completely different (ease strings) | `migrateParams` best-effort + toast "some values reset" |

## Shared run / record / sample contract

Use one imperative contract; each engine implements it with its **own** animation API. No shared physics math.

```ts
// src/engines/run-contract.ts

type EngineId = 'spring' | 'motion' | 'gsap';

type SamplePoint = { t: number; value: number }; // t = ms since run start

type RunStatus = 'idle' | 'running' | 'settled' | 'cancelled';

interface SampleSink {
 onSample(p: SamplePoint): void;
 onSettled(meta: { durationMs: number; sampleCount: number }): void;
 onCancel(): void;
}

interface RunTarget {
 /** Mutable scalar the preview reads (spring visual displacement) */
 getValue(): number;
 setValue(v: number): void;
}

interface EngineRunner<Params> {
 id: EngineId;
 run(
 target: RunTarget,
 params: Params,
 from: number,
 to: number,
 sink: SampleSink,
 signal: AbortSignal, // generation / unmount
 ): void; // starts async; must not throw after signal aborted
}
```

### Per-engine recording (real engine paths)

| Engine | Start | Sample hook | Stop/cleanup |
|--------|-------|-------------|--------------|
| **react-spring** | `api.start({ to: { v: to }, from: { v: from }, config, onChange })` | `onChange` gives live `v` | `api.stop()` + cancel `onChange` |
| **Motion** | `animate(mv, to, { type:'spring', ...params })` | `mv.on('change', v => …)` | `controls.stop()` + `mv.clearListeners()` |
| **GSAP** | `gsap.to(proxy, { v: to, duration, ease, onUpdate })` | `onUpdate` → `proxy.v` | `tween.kill()` + `ctx.revert()` via `useGSAP` |

**Rules:**
1. **One run** feeds both `MechanicalSpringVisual` and `GraphView` from the same `RunTarget` / samples buffer.
2. **Record on every callback** with `t = performance.now() - t0`; do not resample analytically.
3. **`AbortSignal`** incremented on unmount, param change, or re-run — ignore stale callbacks (StrictMode).
4. **Settled** = engine's own completion (`onRest` / `controls.then` / `onComplete`), not a shared epsilon (physics engines settle at different rates).

## Physical spring preview

Implemented in [`src/domain/SpringVisualizer.js`](https://github.com/JoostKiens/react-spring-visualizer/blob/master/src/domain/SpringVisualizer.js).

The React Spring animation is:

```text
from progress = 0
to progress = active ? 1 : 0
immediate = !active
config = editor config
```

For a container of height `H`:

```text
restLength = H / 5
initialDisplacement = H / 5
bobTranslateY(p) = initialDisplacement × (1 - p)
```

Thus:

- `p = 0`: bob is one-fifth of the container below equilibrium.
- `p = 1`: bob is at equilibrium.
- `p > 1`: overshoot appears above equilibrium.
- `p < 0`: it moves farther downward.

Visual parameter mappings are separate from the actual spring physics:

- Bob height: `sqrt(mass × 3600) = 60 × sqrt(mass)`
- Friction-arrow scale: `sqrt(friction × 0.015)`
- Spring horizontal scale: `0.5 + tension / 500`
- Spring stroke width: `0.5 + 3.5 × tension / 500`
- Spring vertical scale:

```text
(restLength + initialDisplacement × (1 - p)) / 500
```

The source writes a longer expression containing `maxTension`, but those factors cancel algebraically. That should be simplified in a rewrite.

The drawing is metaphorical: mass, friction, and tension affect the actual React Spring solver, while the SVG’s thickness, width, arrow size, and bob size merely illustrate those values.

## Exact spring physics used

The application delegates integration to `react-spring@9.2.4`. Its solver is in React Spring’s [`SpringValue.ts`](https://github.com/pmndrs/react-spring/blob/v9.2.4/packages/core/src/SpringValue.ts#L257-L310).

The underlying continuous model is:

```text
m x″ + c x′ + k(x - target) = 0
```

Where:

- `m = mass`
- `c = friction`
- `k = tension`

React Spring subdivides every rendered frame into `ceil(frameDelta)` one-millisecond steps. For each step:

```text
springForce = -tension × 0.000001 × (position - target)
dampingForce = -friction × 0.001 × velocity
acceleration = (springForce + dampingForce) / mass

velocity += acceleration
position += velocity
```

This is a semi-implicit Euler update in millisecond units.

Stopping thresholds:

```text
precision = config.precision
restVelocity = config.restVelocity || precision / 10
finished = abs(velocity) <= restVelocity
 && abs(target - position) <= precision
```

Because the editor always supplies precision, its fallback calculation is not used.

Initial velocity comes directly from the editor’s `velocity` field. The small `±0.05` range reflects the solver’s millisecond velocity units.

## Clamp

Clamp has two independent effects:

1. It is passed directly to React Spring.
2. It adds a drawn barrier at the dashed equilibrium line through CSS.

In React Spring 9.2.4:

```text
bounceFactor = clamp ? 0 : bounce
```

When the value reaches or crosses the target:

```text
velocity = -velocity × bounceFactor
position = target
```

With clamp enabled, `bounceFactor` is zero, so velocity becomes zero and overshoot ends immediately. This is solver behavior, not a CSS clipping trick.

The barrier rendering is in [`SpringVisualizer.css`](https://github.com/JoostKiens/react-spring-visualizer/blob/master/src/domain/SpringVisualizer.css#L72-L88).

## Graph-over-time view

Collection happens inside [`SpringVisualizer.js`](https://github.com/JoostKiens/react-spring-visualizer/blob/master/src/domain/SpringVisualizer.js#L33-L52):

- `onStart`: clears `valuesRef` and records `performance.now()`.
- `onChange`: pushes the current `progress`.
- `onRest`: calculates wall-clock duration and stores the samples.
- After another 360 ms, the physical drawing is replaced by `Chart`.

Rendering is in [`src/domain/Chart.js`](https://github.com/JoostKiens/react-spring-visualizer/blob/master/src/domain/Chart.js).

For sample `i` among `N` samples:

```text
xᵢ = i / (N - 1) × width
```

This is sample index, not elapsed time.

Value-to-Y mapping is:

```text
normalized = (value - min) / (max - min)
mapped = 0.2H + normalized × 0.6H
y = H - mapped
```

Therefore minimum maps to `0.8H`, maximum to `0.2H`.

The chart:

- Smooths points using `svg-catmull-rom-spline`.
- Closes the curve to the bottom to create a filled area.
- Draws dashed reference lines for `progress=0` and `progress=1`.
- Shows duration, minimum, and maximum.
- Creates one React Spring via `useSprings` for every sampled point.
- Delays each point by `10 × index` ms.
- Uses:

```text
easeOutBack(x) =
 1 + 2.70158(x - 1)³ + 1.70158(x - 1)²
```

- Reveals the area with another spring using `{ tension: 380, friction: 40, clamp: true }`.

Important limitations:

- It is not truly “over time”; variable frame spacing is discarded.
- A Catmull–Rom spline can invent visual overshoot between real samples.
- There is no explicit initial `{t:0,value:0}` point.
- `min === max` would divide by zero.
- `Math.min(...values)` and one spring per point do not scale well.
- Every point’s `onRest` restarts the mask animation.
- Only Spring mode transitions to this graph.
